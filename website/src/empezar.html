Empezar

Tu primera partida.

Prepará el contenido, compilá el proyecto y comenzá en Northolt Park. Esta web presenta el simulador; la partida se ejecuta en tu equipo.

Antes de salir

Prepará el equipo.

Linux es la plataforma de referencia. Necesitás Rust {{rust}} o superior, Git y el contenido Chiltern de MSTS/Open Rails. Los recursos de terceros se instalan por separado.

  1. 01

    Descargá el código

    git clone https://github.com/cavazquez/openrailsrs.git
cd openrailsrs
  2. 02

    Ubicá el contenido Chiltern

    El lanzador busca por defecto en ~/Documentos/Open Rails/Content/Chiltern/ROUTES/Chiltern. Si está en otra carpeta, indicá la ruta:

    export CHILTERN_ROUTE="/ruta/al/Content/Chiltern/ROUTES/Chiltern"
    Guía del contenido original ↗
  3. 03

    Compilá e iniciá el menú

    ./scripts/run_chiltern_service.sh

    El lanzador compila los componentes. En el primer inicio puede tardar; la pantalla de carga espera también las mallas, texturas y shaders.

  4. 04

    Elegí el servicio y salí

    Seleccioná Chiltern y el recorrido extendido de seis estaciones. También podés probar el servicio corto, la hora, la estación del año y el clima.

    # Iniciar directamente el servicio extendido
./scripts/run_chiltern_service.sh --direct

Si falla la compilación o el controlador gráfico, consultá la guía de Bevy y las pruebas del visor.

Tu equipo

Elegí cómo
calcular y dibujar.

En F10, Cálculo del clima cambia entre automático, GPU, CPU y mixto. Renderizado al iniciar selecciona el adaptador y requiere reiniciar el visor.

GPU
Dibuja la escena con aceleración y calcula las trayectorias de la precipitación en el shader. Física y señales permanecen en CPU.
CPU + GPU
La CPU calcula todos o parte de los copos; la GPU dibuja. Automático reduce el detalle del clima ante presión sostenida.
CPU por software
Dibuja también la escena en CPU, mediante un adaptador compatible como Mesa lavapipe. Sirve como alternativa funcional; puede ser mucho más lento.
# Nieve y cálculo de partículas en GPU
OPENRAILSRS_WEATHER=snow OPENRAILSRS_WEATHER_EXECUTION=gpu \
  ./scripts/run_chiltern_service.sh --direct --renderer gpu

# Nieve con cálculo mixto y renderizado automático
OPENRAILSRS_WEATHER=snow OPENRAILSRS_WEATHER_EXECUTION=hybrid \
  ./scripts/run_chiltern_service.sh --direct --renderer auto

# Renderizado completo por software (requiere adaptador compatible)
./scripts/run_chiltern_service.sh --direct --renderer cpu

F8 → Diagnóstico muestra RAM, VRAM disponible y reparto del clima. RAM y VRAM no se suman como si fueran memoria independiente. El renderizador completo no cambia de dispositivo durante la partida.

Tu biblioteca

Contenido del autor, ediciones independientes.

Desde el menú podés descargar Demo Model 1 (260 MiB; 315 MiB instalado), buscar actualizaciones y reauditar una copia sin conexión. La formación original de siete vehículos dispone de cabina 3D; los Include nativos se leen antes de auditar e iniciar.

Las copias nuevas de Chiltern conservan las anteriores y muestran fecha del origen e identificador. Los paquetes quedan fuera de Git, en datos del usuario: Linux usa XDG y Snap su carpeta común entre revisiones. El instalador y catálogo están embebidos; descargar requiere Python 3. El Snap real todavía necesita empaquetado y validación.

Los faltantes enlazan al repositorio original cuando se conoce. El CAF 6000 sintético del ejemplo Mitre es un marcador: el modelo de Vapor3D se ofrece como alternativa Metro/Subte B, pendiente de validar.
